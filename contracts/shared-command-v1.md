# Shared command boundary — proposed v1 only

No public endpoint is deployed. Resolve site/company/service scope from the authenticated server registry; company_id is a requested binding to validate, never routing authority. Actor/roles/delegation come from current authenticated server context, never payload fields. operation is policy-allowlisted, not arbitrary ORM method invocation. Each operation still needs its own typed payload schema; the envelope alone cannot validate a financial/stock command. Unknown fields/versions and unknown policy/BOM versions reject before mutation. No bank-payment or tax-filing operation exists.

Normalize operation-specific payload: exact decimal strings/base UOM, canonical keys, timezone dates and sorted sets only where order has no meaning. Compare normalized payload hash and immutable BOM/policy snapshot under one durable key(company,source,operation/version,external_key). Do not infer semantic equivalence from arbitrary client JSON or currency floats. Server computes the hash. command_id is correlation, not a bypass for unique external_key. Validate nested item/warehouse/account/customer IDs belong to bound company and approved mapping. Reserve/release/dispatch require expected command/order state/version and whole component locking. Queue actor/registry references, not bearer tokens or cached authorization claims.

Result design: command_id, durable key, state(PENDING|COMPLETED|REJECTED|CANCELLED), original immutable native document references and projection version. Exact duplicate returns the original result/current terminal state; a different normalized payload under the same key yields409 conflict; forbidden company/site yields403; unsupported policy/input yields422; transient retry exhaustion yields retryable failure without committed partial success. Cancelled replay remains cancelled and never reserves/posts again. ACK records/outbox receipts do not form another financial or stock ledger. New idempotency key must not enable an over-order shipment; order/document state constraints remain native and locked.

Transport delivery is at-least-once; receiver persists unique receipt atomically with its side effect. Postcommit sender crash leaves durable outbox retryable. Cross-site intercompany uses a correlated recoverable saga, not an alleged global DB transaction. Clients cannot use direct native write/export/admin routes to bypass these checks. Future endpoint implementation remains gated by explicit owner start approval and native/UI/security tests.
