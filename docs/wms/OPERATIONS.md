# Warehouse operation state machines

Transitions are server-authored transactions with expected aggregate version, operation key, actor, source lines, quantity, timestamp and immutable evidence. Scanning produces proposed commands; offline scans do not guarantee reservations until server acceptance. Printing is always a separate informational action.

| Cycle                 | Ordered states and stock effect                                                                 | Exceptions                                                                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Purchasing/receipt    | PO open → arrive → received into receiving/quarantine → inspect → accept/reject → putaway       | Partial receipt/rejection by line; excess needs explicit policy; duplicate delivery event adds no stock                                      |
| Putaway/internal move | source location reserve → scan destination → complete paired location deltas                    | Wrong bin/item/lot rejected; same owner and warehouse validated; missing scan remains a task                                                 |
| Sales                 | normalized → mapped → reserved OR shortage exception                                            | No inferred mapping on ambiguous identifiers; FBB tracked separately                                                                         |
| Picking               | reserved → pick task → partial/full picked                                                      | Quantity and item/location scan; unavailable pick creates discrepancy, not unlogged adjustment                                               |
| Packing               | picked → pack contents verified → packaging recorded                                            | Over/under pack blocks dispatch; repack retains history                                                                                      |
| Shipping              | packed → official label provider-readback → handoff verified → dispatched                       | Label matches org/account/order/shipment; printing/reprinting cannot dispatch or repurchase; actual dispatch consumes physical+reserved once |
| Cancellation          | unshipped remaining → cancelled/released                                                        | Race with dispatch serialized; shipped quantities require returns; cancellation cannot reset provider state blindly                          |
| Return                | original shipment → return authorized/received → quarantine → inspection → restock/repair/scrap | Quarantine never sellable; restock only inspected quantity, original cost layer retained when possible                                       |
| Damage                | discrepancy detected → segregate → approved scrap/adjustment                                    | Never quietly rewrite physical balance; reserved damaged goods require reallocation or shortage                                              |
| Transfer              | draft → reserve source → dispatch to transit → receive destination → reconcile                  | Source+transit+destination conserved; transit unavailable; partial receipts/loss documented; no cross-company internal transfer              |
| Count                 | scope snapshot → blind count → variance → approval → adjustment                                 | Concurrent movements reconciled by snapshot/version; do not overwrite a newer live balance                                                   |

Reorder suggestions use reliable demand history, lead-time and inbound receipts; projections show coverage and confidence. A suggestion does not create a purchase order or payment without its own authorization. Batch/lot/serial and expiry constraints apply before picking when the item policy requires them.

Required evidence by dispatch: verified reserved order/line quantities, pick confirmation, pack check, official label metadata when applicable, and actual carrier handoff evidence. An internal printable list is not a carrier label. A warehouse-event pure validator is not proof that the server persisted this workflow.
