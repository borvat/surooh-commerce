## Scope and entry points

`verification/run.py` runs actual commands on a clean exact Git checkout, with allowlisted synthetic environment variables. It continues after failed tests to record the complete available picture. `verification/plan.json` declares test tiers, commands, unavailable cases and phase requirements. `verification/gate.py` independently validates exact source SHA, source cleanliness, required executed tests/tiers, command/exit code, logs/artifact hashes and plan hash. It returns BLOCKED or READY_FOR_HUMAN_EVIDENCE_REVIEW, **never phase-complete or execution approval**. Review provenance/identity still requires a human; local JSON is not cryptographic proof of execution or protected branch enforcement.

No Docker/cloud/paid service is required for offline/UI checks. Native replay requires the explicitly prepared local synthetic ERPNext/Frappe16.52/MariaDB11.8.9/Redis7.0.15 fixture; fresh provisioning is not provided by this replay. A Linux executor mapping only UID0 cannot prove separate service identities/mounts. Full WMS legacy Supabase-compatible migration/RLS runner remains unimplemented and exits2. A running DB process or unit/static-SQL test is not DB/RLS acceptance.

## Evidence contract and review

Each fresh output directory contains report.json, redacted command logs and whitelisted build/native artifacts. Report records source commit/tree, source status before/after, UTC timestamps, environment/tool versions, input hashes, exact argv/cwd, per-test exit/status/duration, sanitized log hashes and raw-output digests. Source changes generated by build are reported and block review until reconciled against a reviewed clean snapshot; do not silently restore/edit source to green a test. Never weaken compiler/lint settings or broadly format WMS source.

Use a new output directory every run. Never upload HOME caches, bench/site configs, DB dumps/backups, private files or keys; native replay stages backup data in a temporary directory and exports JSON/logs/version metadata only. Do not archive the whole runtime/bench. Redaction is a defense, not permission to pass production secrets. All tests are synthetic; environment allowlisting is not a network/host isolation guarantee.

The gate rejects missing/failed/blocked/skipped mandatory tests, stale SHAs, missing commands/logs, tampered/traversing artifacts and reference-to-native tier substitution. It cannot prove a malicious author really ran commands: reviewer checks logs, source/runtime digests, expected test assertions and provenance. Required review record: exact tested Accounting/WMS commits, evidence/report SHA256, each required tier, failure/blocked disposition, reviewer identity and real review reference. Fiscal approval requires an actual qualified Dutch accountant. No self-signed approval is created.

Test code is committed before the full run. A later evidence-only commit records results; its Git SHA differs from the tested source SHA. Always review/replay the report's tested commit; do not advertise the later evidence head as the executed source. Any functional/test/dependency/plan change invalidating evidence needs a new run. Evidence-only publication does not authorize the next phase, Codex, merge, deployment or real migration.
